The judgments that need fresh context. Everything else is in the raw
sessions under `docs/retro/raw/`, mined at phase close.

**Scope**
- Skills name docs by what they are and run one `cdd` command for
  starting, reading, claiming and merging. The repo restructure then edits
  `cdd` alone. The restructure, 001-010, then moves the files.

**Planning miss**
- The architecture decided a skill names a doc as a file it reads or
  writes. It never weighed the files moving. Architecture.

**Deviations from the plan and design**
- Each of the six tickets holds one feature. 001-008 runs after 001-009, or main fails
  its own check.
- The architecture's Foundations section is now Base, so it doesn't clash
  with each app's own foundations.
- The restructure runs after the skills lose their paths, so each path changes once.
- Decisions get tests, so the design names no skills.
- The four `cdd` features became decisions. They were tools, not ways a step can go.
- A new form, Component, holds an architecture part's decisions. Keeping each fact in its place becomes the Checks component in 001-011.
- Features are the only bridge from the design. A skill per workflow is one tested decision, not a component each.
- The architecture over its cap under Scripts until 001-011 splits it into components.
- Foundations is a doc the Product Owner is accountable for, not a form.
